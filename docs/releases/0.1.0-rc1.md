## Browser and accessibility evidence

The local OIDC journeys were exercised with Chromium 151 against the rebuilt Actix container.
The documented development identity was used; no production credential was involved.

- The login page exposed a `main` landmark, a named `Welcome back` region, one level-one heading,
  named text/password fields, named password-toggle and submit buttons, and a status region.
- The `Email address` and `Password` labels were associated with `login_identifier` and
  `login_password` respectively.
- At a 320 by 800 CSS-pixel viewport, document width remained 320 pixels and there was no
  horizontal overflow.
- Browser-computed focus styling was visible on the identifier, password, password-toggle, and
  submit controls (a three-pixel outline; the fields also had a focus ring).
- Invalid credentials focused the alert, cleared the password field, and retained only the
  non-sensitive identifier. The browser remained at 320 CSS pixels without horizontal overflow.
- The consent screen identified the client and scopes, exposed named `Allow access` and `Cancel`
  actions, and remained free of horizontal overflow at 320 CSS pixels.
- Consent denial returned `access_denied` with the original state; consent approval returned an
  authorization code with the original state and issuer.
- The protocol-error screen exposed a named region, level-one heading, alert, correlation
  reference, and return-home action without horizontal overflow at 320 CSS pixels.
- The logout confirmation exposed a named region, heading, `Sign out` action, and
  `Keep me signed in` alternative; confirmation reached the signed-out page.
- A real OAuth2 Proxy browser callback authenticated the user and established the RP session.
- Browser testing exposed a CSP defect that blocked a registered cross-origin form handoff. The
  fix now adds only the exact registered redirect origin to `form-action`; a Rust unit test and
  `make rp-smoke` both guard the behavior without admitting the redirect path or query.

These checks cover the visual/semantic browser journeys and responsive 320-pixel layouts. Browser
automation used pointer-style activation for some controls, so it does not replace the remaining
keyboard-only and assistive-technology checks below.

## Deployment observation

The initial public check returned HTTP 502 because Caddy targeted loopback port 4042 while the
release Compose default targeted 4001. The release default and documentation now use 4042, leaving
the development stack independently available on 4001. A second defect—mode-`0600` Compose secret
bind mounts being unreadable by the image UID—was fixed by explicitly running the application as
the non-root numeric file owner. The final public and internal checks above passed on the exact
rebuilt image. No production secret value was printed or committed.
